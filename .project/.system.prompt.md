# Development System Guide

## Project Structure Overview
```
.project/
├── 00_project_overview/     # Project vision, MVP, roadmap
├── 01_feature_specs/        # Feature specifications and tasks
├── 02_ux_docs/             # User experience documentation
└── 03_technical_docs/      # Technical architecture and design
```

## Development Workflow

### 1. Understanding Context
- Start with `00_project_overview/00_mvp-specification.md` for project scope
- Review `01_high_level_roadmap.md` for current phase and priorities
- Check `key_references/` for relevant diagrams or external docs

### 2. Feature Development
When working on a feature:
1. Locate feature in `01_feature_specs/FXXX_Feature_Name/`
2. Review main spec file for overall context
3. Check the subfeatures folder for detailed requirements
4. Reference tasks for implementation steps
5. Update task status as you progress

NOTE: Subfeatures may contain additional subfeature folders that contain more detailed requirements.

### 3. Technical Reference
- Architecture docs in `03_technical_docs/architecture/`
- API specs in `03_technical_docs/api/`
- Design decisions in `03_technical_docs/design/`

### 4. UX Guidelines
- User flows in `02_ux_docs/journey_maps/`
- UI components in `02_ux_docs/wireframes/`

## Development Guidelines

### 1. Code Implementation
- Follow MVP approach - keep it simple
- Use standard library where possible
- Write tests using standard library
- Document decisions and rationale
- Update relevant documentation

### 2. Testing
- Write tests for all new code
- Use standard library testing
- Follow got/want pattern
- Test edge cases
- Document test scenarios

### 3. Documentation
- Keep READMEs up to date in each package and subpackage
- Keep `./project/03_technical_docs/` up to date with the latest design decisions, architecture, and API specs
- Keep the `## Implementation Status` section of each feature spec up to date with the latest implementation progress with references to the relevant files
- Note dependencies
- Update status indicators

### 4. Code Review
- Check against specifications
- Verify test coverage
- Review documentation
- Validate against UX guidelines
- Ensure MVP compliance

## Quick Reference

### Feature Development
1. Find feature spec: `01_feature_specs/FXXX_Feature_Name/`
2. Review requirements
3. Check dependencies
4. Implement code
5. Write tests
6. Update docs
7. Update status

### Technical Questions
1. Check architecture docs
2. Review API specs
3. Consult design decisions
4. Reference implementation examples

### UX Questions
1. Check journey maps
2. Review wireframes
3. Validate against guidelines
4. Document changes

Remember: Keep it simple, focus on MVP, maintain documentation, and follow established patterns.
