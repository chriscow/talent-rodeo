# SF004.1: Location Preferences

## Subfeature Overview
This subfeature enables candidates to specify their location preferences for job searches, allowing the system to filter job opportunities based on these preferences. Searching for LinkedIn jobs
requires a `geoid` which we do not currently have. GeoIDs can represent a city, state, zip code or even a metro area and even "Remote" positions. For the MVP, location filtering will focus on supported metropolitan areas which will be hard-coded including fully remote positions.

## Detailed Specifications

### Current Implementation References
- Database schema in `/workspaces/talent-rodeo/assets/migrations/000002_create_users_and_onboarding_tables.up.sql`: Contains the `candidate_preferences` table
- Basic UI in `/workspaces/talent-rodeo/cmd/web/handlers.preferences.go`: Displays preferences form but does not process form data

### Technical Requirements
- Implement a dropdown UI component for location selection
- Add "Fully Remote" option with a dedicated GeoID
- Include the top 5 metropolitan areas with hard-coded GeoIDs
- Store the selected location preference in the `candidate_preferences` table
- Apply location filter to search results before scoring
- Add clear messaging about future preference enhancements

### Location Handling Strategy
- Use a hard-coded lookup table of GeoIDs for supported metropolitan areas
- Provide "Fully Remote" as a separate option with its own GeoID
- Only exact matches will be considered in the MVP (no partial matches)
- Clear UI messaging will indicate the limited scope of supported locations

## Error Handling
- If location preference is not set, users will be prompted to select one
- Invalid location selections will default to "Fully Remote"
- Clear messaging if no jobs match the selected location
