# T004.1.2: Preference Storage

## Task Description
Implement the backend functionality to store and retrieve user location preferences in the database. This includes updating the preference handling in the form submission handler and creating a GeoID mapping service.

## Acceptance Criteria
1. The `updatePreferences` handler correctly processes the location preference from form data
2. Location preference is stored in the `candidate_preferences` table
3. A GeoID mapping service is implemented to translate UI location values to standard GeoIDs
4. Previously selected preferences are correctly retrieved and displayed in the UI
5. Changes to location preferences are properly logged for auditing

## Implementation Details
1. Update the `updatePreferences` function in `/cmd/web/handlers.preferences.go` to process form data:
   ```go
   // Extract location preference from form
   locationPref := r.FormValue("location_preference")
   
   // Validate location preference
   if !isValidLocationPref(locationPref) {
       locationPref = "remote" // Default to remote if invalid
   }
   
   // Get GeoID for the location preference
   geoID := mapLocationToGeoID(locationPref)
   
   // Store in database
   err = app.preferences.UpdateLocationPreference(userID, geoID)
   if err != nil {
       app.serverError(w, err)
       return
   }
   ```

2. Create a GeoID mapping service in `/internal/service/geoid.go`:
   ```go
   // Hard-coded mapping of location keys to GeoIDs
   var locationGeoIDMap = map[string]string{
       "remote": "remote-001",
       "sf": "us-ca-sfbay-001",
       "nyc": "us-ny-nyc-001",
       "sea": "us-wa-sea-001",
       "aus": "us-tx-aus-001",
       "bos": "us-ma-bos-001",
   }
   
   // MapLocationToGeoID converts a location preference key to a standard GeoID
   func MapLocationToGeoID(locationKey string) string {
       if geoID, exists := locationGeoIDMap[locationKey]; exists {
           return geoID
       }
       return locationGeoIDMap["remote"] // Default to remote
   }
   
   // GetLocationKeyFromGeoID converts a GeoID back to a location key for UI
   func GetLocationKeyFromGeoID(geoID string) string {
       for key, val := range locationGeoIDMap {
           if val == geoID {
               return key
           }
       }
       return "remote" // Default to remote
   }
   ```

3. Implement database operations in `/internal/models/preferences.go`:
   ```go
   // UpdateLocationPreference updates the user's location preference
   func (p *PreferenceModel) UpdateLocationPreference(userID int, geoID string) error {
       stmt := `
           INSERT INTO candidate_preferences (user_id, preference_key, preference_value, updated_at)
           VALUES ($1, 'location_geo_id', $2, NOW())
           ON CONFLICT (user_id, preference_key) 
           DO UPDATE SET preference_value = $2, updated_at = NOW()
       `
       
       _, err := p.DB.Exec(stmt, userID, geoID)
       return err
   }
   
   // GetLocationPreference retrieves the user's location preference
   func (p *PreferenceModel) GetLocationPreference(userID int) (string, error) {
       var geoID string
       
       stmt := `
           SELECT preference_value 
           FROM candidate_preferences
           WHERE user_id = $1 AND preference_key = 'location_geo_id'
       `
       
       err := p.DB.QueryRow(stmt, userID).Scan(&geoID)
       if err == sql.ErrNoRows {
           return "remote-001", nil // Default to remote if not set
       }
       return geoID, err
   }
   ```

## Technical Notes
- The GeoID format follows a standard pattern: `[country]-[state/region]-[city]-[sequence]`
- Remote jobs have a special GeoID format: `remote-[sequence]`
- Consider adding logging for preference changes to aid in debugging
