# T004.1.3: Location Filter Integration

## Task Description
Implement the integration of location preferences with the job search functionality to filter job results based on the user's location preference before applying match scoring.

## Acceptance Criteria
1. Job search results are filtered based on the user's location preference
2. Jobs with matching GeoIDs are included in results
3. Remote jobs are included when the user's preference is set to "Fully Remote"
4. Clear messaging is shown when no jobs match the location filter
5. Performance impact on search is minimal (<100ms additional processing time)

## Implementation Details
1. Update the job search handler in `/internal/handlers/search.go` to apply location filtering:
   ```go
   // Get user's location preference
   userGeoID, err := app.preferences.GetLocationPreference(userID)
   if err != nil {
       app.serverError(w, err)
       return
   }
   
   // Apply location filter to jobs before scoring
   var filteredJobs []models.Job
   for _, job := range jobs {
       // Include job if it matches user's location or is remote when user wants remote
       if job.GeoID == userGeoID || 
          (strings.HasPrefix(userGeoID, "remote") && strings.HasPrefix(job.GeoID, "remote")) {
           filteredJobs = append(filteredJobs, job)
       }
   }
   
   // Check if we have any jobs after filtering
   if len(filteredJobs) == 0 {
       // Set appropriate message for no results
       app.session.Put(r, "flash", "No jobs match your location preference. Try selecting a different location.")
       http.Redirect(w, r, "/preferences", http.StatusSeeOther)
       return
   }
   
   // Continue with match scoring using filtered jobs
   scoredJobs := scoreJobs(filteredJobs, userSkills)
   ```

2. Update the job model in `/internal/models/jobs.go` to include GeoID:
   ```go
   // Ensure Job struct has GeoID field
   type Job struct {
       ID          int
       Title       string
       Company     string
       Description string
       GeoID       string
       // other existing fields
   }
   ```

3. Update the job repository to include GeoID in queries:
   ```go
   // Update GetJobs query to include GeoID
   const getJobsQuery = `
       SELECT id, title, company, description, geo_id, created_at, updated_at
       FROM jobs
       WHERE ...
   `
   ```

4. Add appropriate indexing for GeoID field to optimize filtering:
   ```sql
   -- Add to database migration
   CREATE INDEX idx_jobs_geo_id ON jobs(geo_id);
   ```

## Technical Notes
- The job search flow should be:
  1. Fetch jobs matching search criteria
  2. Apply location filter
  3. Score remaining jobs
  4. Display results
- Consider caching location preference to avoid DB lookup on every search
- Remote jobs should match any "remote-XXX" GeoID for flexibility
