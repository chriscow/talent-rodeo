# SF004.2: Database Schema

## Subfeature Overview
This subfeature implements a simplified database schema for storing job matches and skill matches. It consolidates the previously planned six match-related tables into two streamlined tables to support the MVP requirements while maintaining flexibility for future enhancements.

- **Skill Matches Table**: Not Implemented

### Simplified Schema Design
#### 1. `job_matches` Table
```sql
CREATE TABLE job_matches (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    job_id INTEGER REFERENCES jobs(id),
    initial_score INTEGER,
    match_percentage INTEGER,
    is_match BOOLEAN,
    job_match_analysis TEXT, -- extensive chain-of-thought reasoning
    job_match_summary TEXT, -- This is what is presented to the user
    user_feedback TEXT,
    user_feedback_category VARCHAR(50),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### 2. `skill_matches` Table
```sql
CREATE TABLE skill_matches (
    id SERIAL PRIMARY KEY,
    job_match_id INTEGER REFERENCES job_matches(id),
    skill_id INTEGER REFERENCES candidate_skills(id),
    is_match BOOLEAN,
    match_confidence FLOAT,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Database Field Explanations
#### job_matches Table
- `id`: Primary key for the match record
- `user_id`: Reference to the user (candidate) this match belongs to
- `job_id`: Reference to the job being matched
- `initial_score`: Raw score before normalization (sum of skill points)
- `match_percentage`: Normalized score as a percentage (0-100)
- `is_match`: Boolean indicating LLM's final determination (TRUE for match, FALSE for non-match)
- `job_match_analysis`: Detailed LLM analysis with chain-of-thought reasoning
- `job_match_summary`: Concise summary for display to the user
- `user_feedback`: Free-text feedback from the user (optional)
- `user_feedback_category`: Categorized feedback (e.g., "Interested", "Not Interested")
- `created_at` and `updated_at`: Timestamp tracking

#### skill_matches Table
- `id`: Primary key for the skill match record
- `job_match_id`: Reference to the job match this skill match belongs to
- `skill_id`: Reference to the candidate skill being matched
- `is_match`: Boolean indicating if the skill was found in the job
- `match_confidence`: Confidence level of the skill match (0.0-1.0)
- `created_at`: Creation timestamp
