# SF002.1: Automated Outbound Calling

## Overview
The Automated Outbound Calling subfeature enables the system to schedule and initiate phone calls to candidates who have completed their profile creation and provided a phone number. This is a critical component of the assessment process, allowing the system to gather information directly from candidates through natural conversation.

### Call Scheduling Architecture

The system uses a multi-layer architecture for scheduling and making calls:

1. **User Interface Layer**: 
   - Candidate selects a date/time for their call (`handlers.schedule.go`)
   - System creates an appointment record in the database

2. **Task Processing Layer**: 
   - Task processor monitors the database for scheduled appointments
   - When an appointment time arrives, a task is executed

3. **Messaging Layer**: 
   - Task execution publishes a message to NATS JetStream (`message_scheduler.go`)
   - Message contains the phone number and call metadata
   - Published to the `rodeo.voice.input` topic

4. **Execution Layer**: 
   - Voice handler receives message from NATS (`voice.go`)
   - Uses Twilio client to make the actual phone call
   - Publishes results back to NATS on `rodeo.voice.result` topic

This architecture provides decoupling between scheduling and execution, enabling:
- Better scalability with separate components
- Reliable delivery via NATS JetStream
- Automatic retries through the task processor
- Stateless call execution for improved reliability

### Areas for Enhancement

1. **Call Retry Mechanism**
   - While the task processor handles retries for failed tasks, the Twilio client needs improved retry logic for transient failures during call execution
   - Need better handling of specific Twilio error conditions
   - Need to implement phone number validation and formatting
   - No answer, busy or answering machine should be handled gracefully (ask about documentation from Twilio)

2. **Call Status Tracking**
   - Need to implement webhook endpoints for receiving Twilio status updates
   - Need better integration between call status and appointment status
   - Need to update appointment records with call outcomes

### OpenAI Realtime API and Twilio Integration

The system leverages OpenAI's Realtime API for natural conversation and Twilio for telephony. The integration is implemented in `internal/voice` with a sample project demonstrating the flow in `cmd/try/outbound-phone` and `cmd/try/web-call-gpt4o`.

#### Integration Architecture

1. **Audio Flow**
   - Twilio sends base64-encoded audio via WebSocket
   - Audio is processed through an input pipeline for quality/silence detection
   - Audio is sent to OpenAI's Realtime API via WebSocket
   - OpenAI processes the audio and returns responses
   - Responses are processed through an output pipeline
   - Processed audio is sent back to Twilio

2. **Key Components**
   - `Session`: Manages voice chat interaction lifecycle between Twilio and OpenAI
   - `Coordinator`: Coordinates bidirectional audio streams
   - `OpenAIClient`: Handles WebSocket connection to OpenAI Realtime API
   - `TwilioAudioWriter`: Manages sending audio back to Twilio
   - `ProcessingPipeline`: Handles audio transformations and analysis
   - `ConversationRecorder`: Records the audio conversation for future reference

3. **Library Usage**
   - Uses `github.com/chriscow/go-openai-realtime` library for OpenAI integration
   - References to this library can be found in `internal/voice/openai.go`
   - Sample usage is available in `cmd/try/outbound-phone/websocket.go` and `cmd/try/web-call-gpt4o/main.go`

4. **Audio Processing**
   - Recording functionality implemented in `internal/voice/recorder.go`
   - Silence detection in `internal/voice/silence.go`
   - Audio buffering in `internal/voice/buffer.go`

## Detailed Requirements

### Call Scheduling Interface
1. Present an intuitive interface for candidates to select preferred call times
2. Allow selection of date and time within reasonable bounds (e.g., next 7 days)
3. Present time slots in the user's local timezone
4. Respect scheduling preferences from the `scheduling_preferences` table if available
5. **Note: There are no business hours restrictions - users can schedule calls at any time that works for them**
6. Confirm the selected slot with clear feedback
7. Allow rescheduling with appropriate limitations

### Telephony Integration
1. Integrate with a telephony service provider (e.g., Twilio) for outbound calling
2. Configure caller ID to use a recognizable, consistent number
3. Handle international calling requirements for global candidates
4. Support fallback mechanisms when calls cannot be connected
5. Implement call status tracking (initiated, connected, completed, failed)
6. Manage call duration within reasonable limits (typically 15-30 minutes)
7. Handle call termination gracefully (both normal and unexpected)

### Call Scheduling Logic
1. Store appointment data including:
   - User ID
   - Scheduled time (in UTC with timezone info)
   - Status tracking
   - Call metadata (SID, duration, etc.)
2. Implement scheduling validation to prevent:
   - Double-booking time slots
   - Scheduling in the past
   - Scheduling too far in the future (e.g., > 14 days)
   - **Note: No restrictions on time of day - calls can be scheduled 24/7 based on user preference**
3. Create appropriate database entries for scheduled calls
4. Update user onboarding state upon successful scheduling
5. Generate calendar invites/reminders (optional enhancement)

### Call Execution
1. Schedule tasks to run at appointment times via the task processor
2. Publish messages to NATS at the scheduled time
3. Process messages via the Voice Handler to initiate calls
4. Handle connection attempts with retry logic for failed connections
5. Pass control to the conversation handler once connected
6. Update appointment status throughout the call lifecycle
7. Record call metadata (start time, duration, outcome)

### Error Handling
1. Implement graceful handling for common failure scenarios:
   - Candidate doesn't answer
   - Line busy or unavailable
   - Network/telephony service disruptions
   - Call dropped mid-conversation
2. Provide appropriate user notifications for call issues
3. Implement retry policies for failed connection attempts
4. Log detailed error information for diagnostics

## User Experience
1. Present a clean, intuitive scheduling interface
2. Provide clear confirmation of scheduled appointments
3. Send reminders prior to scheduled calls (email/SMS)
4. Set expectations for call purpose and duration
5. Provide options to reschedule if needed
6. Display upcoming appointment information in user dashboard

func scheduleAppointment(w http.ResponseWriter, r *http.Request) {
    user := getUserFromContext(r)
    
    // Parse form data
    if err := r.ParseForm(); err != nil {
        renderError(w, "Invalid form submission")
        return
    }
    
    // Get date and time from form
    dateStr := r.FormValue("date")
    timeStr := r.FormValue("time")
    
    // Parse timezone
    userTimezone := r.FormValue("timezone")
    if userTimezone == "" {
        userTimezone = "UTC" // Default fallback
    }
    
    // Parse and validate date/time
    scheduledTime, err := parseDateTime(dateStr, timeStr, userTimezone)
    if err != nil {
        renderError(w, "Invalid date or time selected")
        return
    }
    
    // Validate scheduling constraints
    if err := validateSchedulingConstraints(scheduledTime, userTimezone); err != nil {
        renderError(w, err.Error())
        return
    }
    
    // Create appointment record
    appointmentID, err := createAppointment(db, user.ID, scheduledTime, userTimezone)

        renderError(w, "Failed to schedule appointment")
        return

        logger.Error("Failed to update onboarding state", "error", err)

### Call Execution Worker Example
```go
func processScheduledCalls() {
    // Find appointments scheduled within the next minute
    query := `
        SELECT id, user_id, scheduled_time, timezone 
        FROM appointments 
        WHERE status = 'scheduled' 
        AND scheduled_time BETWEEN NOW() AND NOW() + INTERVAL '1 minute'
    `
    
    rows, err := db.Query(query)
    if err != nil {
        logger.Error("Failed to query upcoming appointments", "error", err)
        return
    }
    defer rows.Close()
    
    for rows.Next() {
        var appt Appointment
        if err := rows.Scan(&appt.ID, &appt.UserID, &appt.ScheduledTime, &appt.Timezone); err != nil {
            logger.Error("Failed to scan appointment row", "error", err)
            continue
        }
        
        // Process each appointment in a goroutine
        go func(appointment Appointment) {
            // Get user phone number
            phone, err := getUserPhone(db, appointment.UserID)
            if err != nil {
                logger.Error("Failed to get user phone", "error", err)
                updateAppointmentStatus(db, appointment.ID, "failed")
                return
            }
            
            // Initiate call via telephony provider
            callSID, err := initiateCall(phone, appointment.ID)
            if err != nil {
                logger.Error("Failed to initiate call", "error", err)
                updateAppointmentStatus(db, appointment.ID, "failed")
                return
            }
            
            // Update appointment with call SID
            updateAppointmentCallSID(db, appointment.ID, callSID)
        }(appt)
    }
}
```
