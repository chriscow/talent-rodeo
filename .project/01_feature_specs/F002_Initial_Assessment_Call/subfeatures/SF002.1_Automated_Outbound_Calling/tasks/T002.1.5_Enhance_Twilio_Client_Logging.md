# T002.1.5: Enhance Twilio Client Logging

## Task Description
Improve the logging in the Twilio client to provide more detailed, structured, and consistent logs for better debugging, monitoring, and troubleshooting of outbound calls.

## Current Implementation Status
The current Twilio client implementation in `internal/tasks/handlers/twilio_client.go` has basic logging, but it lacks consistency, structured metadata, and sufficient detail for production monitoring and troubleshooting.

## Specific Requirements

1. Create a standardized set of log keys to be used consistently across all Twilio client methods:
   ```go
   const (
       logKeyCallSID     = "call_sid"
       logKeyFromNumber  = "from_number"
       logKeyToNumber    = "to_number"
       logKeyCallStatus  = "call_status"
       logKeyDuration    = "duration_ms"
       logKeyAttempt     = "attempt"
       logKeyErrorDetail = "error_detail"
   )
   ```

2. Add detailed logging to the `MakeCall` method:
   - Start with a Debug log showing the intent to make a call
   - Include all relevant parameters (from, to, twiml summary)
   - Log the start time and calculate duration on completion
   - Log at Info level for successful calls
   - Log at Error level for failed calls with detailed error information
   - If retries are implemented, log each retry attempt at Warn level


3. Apply similar enhanced logging to `GetCallStatus` and `EndCall` methods:
   - Log the input parameters at Debug level
   - Log successful operations at Info level
   - Log errors at Error level
   - Include duration in all terminal logs (success or error)

4. Add logging helper methods if needed to reduce code duplication:
   ```go
   func (c *RealTwilioClient) logCallOperation(level slog.Level, msg string, callSID string, duration int64, err error, attrs ...slog.Attr) {
       // Implementation here
   }
   ```

## Acceptance Criteria
1. All Twilio client methods have consistent, structured logging
2. Logs include detailed context information (call SID, phone numbers, duration, etc.)
3. Appropriate log levels are used for different scenarios:
   - Debug: Operation attempts and detailed flow
   - Info: Successful operations
   - Warn: Retry attempts or non-critical issues
   - Error: Failed operations
4. Call durations are logged for performance monitoring
5. Error details are logged with sufficient context to aid debugging
6. Log format is consistent with the rest of the application

## Required Changes
1. Define standardized log keys as constants
2. Update the `MakeCall` method with enhanced logging
3. Update the `GetCallStatus` method with enhanced logging
4. Update the `EndCall` method with enhanced logging
5. Add helper methods if needed to reduce code duplication

## Dependencies
- Existing Twilio client in `internal/tasks/handlers/twilio_client.go`
- Standard library time package for duration measurement
- Structured logging via slog
