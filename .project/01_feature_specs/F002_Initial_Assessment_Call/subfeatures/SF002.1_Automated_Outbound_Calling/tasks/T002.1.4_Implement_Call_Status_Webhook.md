# T002.1.4: Implement Call Status Webhook Endpoint

## Task Description
Create a webhook endpoint to receive and process Twilio call status updates, allowing the system to track call progress and update appointment records with accurate status information.

## Current Implementation Status
A basic webhook handler exists in `internal/voice/webhook.go`, but it lacks specific handling for updating appointment status based on call status updates from Twilio.

## Specific Requirements

1. Extend the existing `WebhookHandler` in `internal/voice/webhook.go` to add a method specifically for call status updates:
   ```go
   // HandleCallStatusUpdate processes Twilio call status webhook callbacks
   // Called when Twilio sends status updates about a call (initiated, ringing, in-progress, completed, etc.)
   func (h *WebhookHandler) HandleCallStatusUpdate(w http.ResponseWriter, r *http.Request) {
       // Implementation here
   }
   ```

2. Add a new route in `cmd/web/routes.go` for the status webhook:
   ```go
   router.Post("/api/webhooks/twilio/call-status", handlers.HandleCallStatusUpdate)
   ```

3. The `HandleCallStatusUpdate` method should:
   - Parse the form data from the Twilio request
   - Extract key fields: `CallSid`, `CallStatus`, `To`, and `From`
   - Validate the request is actually from Twilio (optional in MVP)
   - Look up the appointment associated with the call SID
   - Update the appointment status based on the call status
   - Log appropriate information about the status update

4. Add a new method to the `database.DB` to update appointment status:
   ```go
   // UpdateAppointmentCallStatus updates the status of an appointment based on call status
   func (db *DB) UpdateAppointmentCallStatus(callSID string, callStatus string) error {
       // Implementation here
   }
   ```

5. Map Twilio call statuses to appointment statuses:
   - "initiated", "queued", "ringing" → maintain "scheduled" appointment status
   - "in-progress" → update to "in-progress" appointment status
   - "completed" → update to "completed" appointment status
   - "busy", "no-answer", "failed", "canceled" → update to "failed" appointment status

## Acceptance Criteria
1. The webhook endpoint correctly receives and parses Twilio status update callbacks
2. Appointment records are updated with the appropriate status based on call outcomes
3. Calls that fail to connect (busy, no-answer, failed) are properly marked
4. Successful calls are marked as completed
5. The system logs appropriate details for monitoring and debugging
6. The webhook returns appropriate HTTP responses to Twilio

## Required Changes
1. Add the `HandleCallStatusUpdate` method to `WebhookHandler`
2. Add the database method to update appointment status
3. Register the new route in the router
4. Add proper error handling and logging
5. Add unit tests for the webhook handler

## Dependencies

- Database schema for appointments in `assets/migrations/000006_add_scheduling_tables.up.sql`
