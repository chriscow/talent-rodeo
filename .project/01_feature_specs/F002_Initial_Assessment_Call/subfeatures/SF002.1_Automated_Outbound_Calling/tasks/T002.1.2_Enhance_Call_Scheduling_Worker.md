# T002.1.2: Enhance Call Scheduling with NATS Integration

## Task Description
Enhance the existing call scheduling implementation to improve reliability, error handling, and monitoring. The current implementation already integrates with NATS for message delivery, but requires improvements in validation, error handling, and observability.

## Current Implementation Status
The system already has a functional call scheduling flow:
- Users schedule calls via the UI in `profile-schedule-phone-call.html` 
- The form posts to `/profile/schedule/appointment` endpoint
- The `createAppointment` handler in `cmd/web/handlers.schedule.go` processes this request
- An appointment record is created in the database
- A NATS message is scheduled on the `handlers.TopicVoiceInput` topic
- The Voice Handler processes these messages and initiates calls via Twilio

This is built on top of a robust infrastructure:
- Task processing system in `internal/tasks/processor.go`
- NATS message scheduling in `internal/tasks/handlers/message_scheduler.go`
- Voice handler in `internal/handlers/voice.go`

However, the current implementation needs several enhancements:

1. **Improved Validation**:
   - Basic time validation (not in the past, not too far in the future)
   - Phone number validation before scheduling
   - Proper timezone handling

2. **Error Handling**:
   - Better handling of edge cases
   - Structured error reporting
   - Clearer error messages to users

3. **Observability**:
   - Enhanced logging throughout the call scheduling lifecycle
   - Metrics for monitoring call scheduling success rates
   - Tracing for debugging scheduling issues

   func validateAppointmentTime(t time.Time) error {
       // Validate not in the past

4. Extract the NATS message scheduling logic to a dedicated helper function:
   ```go
   // scheduleCallMessage prepares and schedules a NATS message for the voice call
   func (app *application) scheduleCallMessage(
       ctx context.Context, 
       appointmentID, userID int64, 
       phoneNumber string, 
       scheduledTime time.Time,
   ) error {
       // Create voice call message
       message := map[string]any{
           "to": phoneNumber,
           "appointment_id": appointmentID,
           "user_id": userID,
           "metadata": map[string]string{
               "appointment_id": fmt.Sprintf("%d", appointmentID),
               "scheduled_time": scheduledTime.Format(time.RFC3339),
           },
       }
       
       messageJSON, err := json.Marshal(message)
       if err != nil {
           return fmt.Errorf("failed to marshal voice message: %w", err)
       }
       
       // Create task for scheduling the NATS message
       payload := handlers.NATSMessagePayload{
           Subject: handlers.TopicVoiceInput,
           Data:    messageJSON,
           Metadata: map[string]string{
               "source": "appointment-scheduler",
               "appointment_id": fmt.Sprintf("%d", appointmentID),
           },
       }
       
       payloadJSON, err := json.Marshal(payload)
       if err != nil {
           return fmt.Errorf("failed to marshal NATS payload: %w", err)
       }
       
       // Schedule the task to run at the appointment time
       _, err = app.tasks.CreateAndEnqueueTask(
           ctx, 
           "nats_message", 
           payloadJSON, 
           scheduledTime,
       )
       
       if err != nil {
           return fmt.Errorf("failed to schedule NATS message: %w", err)
       }
       
       return nil
   }
   ```

## System Architecture
The call scheduling system uses the following flow:

1. **User Interface**:
   - User submits the appointment form in `/profile-schedule-phone-call.html`
   - Form posts to `/profile/schedule/appointment` endpoint

2. **API Handler**:
   - `createAppointment` in `handlers.schedule.go` processes the request
   - Validates inputs (time constraints, phone number validity)
   - Creates appointment record in database
   - Updates user onboarding state

3. **Message Scheduling**:
   - Creates task payload with NATS message details
   - Schedules task to run at the appointment time
   - Task type is "nats_message" handled by the MessageScheduler

4. **Task Processing**:
   - When appointment time arrives, the task processor executes the task
   - The MessageScheduler publishes the message to NATS topic `rodeo.voice.input`

5. **Voice Handler**:
   - Receives the NATS message
   - Uses Twilio client to initiate the call
   - Publishes call results back to NATS

This architecture already provides:
- Separation of concerns between scheduling and execution
- Reliable message delivery via NATS
- Automatic retries through task processor
- Scalable, decoupled components

The enhancements in this task aim to improve:
- Input validation and error handling
- Observability through logging and metrics
- User feedback and experience
- System reliability and maintainability
