# T002.1.3: Add Retry Logic to Twilio Client

## Task Description
Implement retry logic in the Twilio client to handle transient failures when making outbound calls. This will improve reliability by automatically retrying failed call attempts due to temporary network issues or Twilio service limitations.

## Current Implementation Status
The current implementation in `internal/tasks/handlers/twilio_client.go` does not have any retry mechanism. If a call attempt fails due to temporary issues, it returns an error immediately without retry.

## Specific Requirements

1. Add configuration options for retry settings to the `RealTwilioClient` struct:
   ```go
   type RealTwilioClient struct {
       client     *twilio.RestClient
       logger     *slog.Logger
       fromNumber string
       config     TwilioClientConfig
   }
   
   type TwilioClientConfig struct {
       MaxRetries    int           // Maximum number of retry attempts (default: 3)
       RetryBaseDelay time.Duration // Base delay between retries (default: 500ms)
       RetryMaxDelay  time.Duration // Maximum delay between retries (default: 5s)
   }
   ```

2. Update the constructor to accept these options with sensible defaults:
   ```go
   func NewRealTwilioClient(accountSID, authToken, fromNumber string, config ...TwilioClientConfig) *RealTwilioClient {
       // Apply default config if none provided
       clientConfig := TwilioClientConfig{
           MaxRetries:    3,
           RetryBaseDelay: 500 * time.Millisecond,
           RetryMaxDelay:  5 * time.Second,
       }
       
       if len(config) > 0 {
           clientConfig = config[0]
       }
       
       // Rest of constructor
   }
   ```

3. Add a helper function to identify transient errors:
   ```go
   // isTransientError determines if an error is likely temporary and worth retrying
   func isTransientError(err error) bool {
       if err == nil {
           return false
       }
       
       errorMsg := err.Error()
       // Check for common transient errors
       return strings.Contains(errorMsg, "timeout") ||
              strings.Contains(errorMsg, "connection refused") ||
              strings.Contains(errorMsg, "too many requests") ||
              strings.Contains(errorMsg, "temporarily unavailable")
   }
   ```

4. Modify the `MakeCall` function to implement exponential backoff retry logic:
   ```go
   func (c *RealTwilioClient) MakeCall(ctx context.Context, from, to, twiml string) (string, error) {
       // Existing parameter validation logic
       
       var callSID string
       var lastErr error
       
       for retry := 0; retry < c.config.MaxRetries; retry++ {
           if retry > 0 {
               c.logger.Warn("retrying call after failure",
                   "retry", retry,
                   "to", to,
                   "error", lastErr)
               
               // Calculate backoff with exponential increase and jitter
               delay := time.Duration(float64(c.config.RetryBaseDelay) * math.Pow(2, float64(retry-1)))
               if delay > c.config.RetryMaxDelay {
                   delay = c.config.RetryMaxDelay
               }
               // Add jitter (±20%)
               jitter := time.Duration(rand.Float64()*0.4 - 0.2) * delay
               delay += jitter
               
               time.Sleep(delay)
           }
           
           // Make the call
           params := &twilioApi.CreateCallParams{}
           params.SetTo(to)
           params.SetFrom(from)
           params.SetTwiml(twiml)
           
           resp, err := c.client.Api.CreateCall(params)
           if err != nil {
               lastErr = err
               
               // Only retry for transient errors
               if !isTransientError(err) {
                   break
               }
               
               continue
           }
           
           callSID = *resp.Sid
           lastErr = nil
           break
       }
       
       if lastErr != nil {
           return "", fmt.Errorf("failed to make call after %d attempts: %w", 
               retry+1, lastErr)
       }
       
       c.logger.Info("Call initiated", 
           "call_sid", callSID,
           "status", *resp.Status,
       )
       
       return callSID, nil
   }
   ```

5. Apply similar retry logic to `GetCallStatus` and `EndCall` methods.

## Acceptance Criteria
1. The Twilio client automatically retries transient failures up to a configured maximum number of attempts
2. Retry delays increase exponentially with each attempt (with jitter for better distribution)
3. Only appropriate transient errors result in retry attempts
4. Permanent errors are returned immediately without retrying
5. Proper logging occurs during retry attempts for debugging
6. Unit tests confirm retry behavior for various error scenarios

## Required Changes
1. Update the `RealTwilioClient` struct to include retry configuration
2. Implement the `isTransientError` helper function
3. Modify `MakeCall`, `GetCallStatus`, and `EndCall` to use the retry logic
4. Add appropriate logging during retry attempts
5. Add unit tests for the retry behavior

- Standard library random and math packages for backoff calculation
