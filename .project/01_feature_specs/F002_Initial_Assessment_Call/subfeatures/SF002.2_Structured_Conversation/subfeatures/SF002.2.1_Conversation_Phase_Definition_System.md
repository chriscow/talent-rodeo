# SF002.2.1: Conversation Phase Definition System

## Overview
The Phase Definition System provides the core configuration and state management for structured conversations. It defines valid conversation phases, their requirements, and transition rules.

## Detailed Requirements

### Phase Manager Implementation
The Phase Manager coordinates with event handlers through a common interface:

```go
type PhaseManager struct {
    currentPhase Phase
    phaseConfig map[Phase]PhaseConfig
    handlers    []EventHandler
    mu          sync.RWMutex
}

type PhaseConfig struct {
    Name         string
    Requirements []Requirement
    Transitions  []ValidTransition
    Prompts      map[string]string
}

func (pm *PhaseManager) RegisterHandler(h EventHandler) {
    pm.handlers = append(pm.handlers, h)
}

func (pm *PhaseManager) RequestTransition(ctx context.Context, to Phase) error {
    pm.mu.Lock()
    defer pm.mu.Unlock()

    if !pm.isValidTransition(to) {
        return ErrInvalidTransition
    }

    // Notify all handlers of pending transition
    for _, h := range pm.handlers {
        if err := h.HandlePhaseTransition(ctx, pm.currentPhase, to); err != nil {
            return err
        }
    }

    pm.currentPhase = to
    return nil
}
```

### Phase Configuration
Each phase is defined with specific requirements and valid transitions:

```yaml
phases:
  introduction:
    requirements:
      - type: greeting_confirmed
        required: true
      - type: candidate_identity_confirmed
        required: true
    transitions:
      - to: skills_assessment
        when: all_requirements_met
    prompts:
      initial: "Hello, I'm calling regarding your application..."
      confirm_identity: "Could you please confirm your name..."

  skills_assessment:
    requirements:
      - type: core_skills_identified
        required: true
      - type: experience_level_confirmed
        required: true
    transitions:
      - to: project_discussion
        when: all_requirements_met
      - to: wrap_up
        when: time_exceeded
    prompts:
      initial: "Let's discuss your technical background..."
```

### Loading Configuration
```go
func loadPhaseConfiguration(configPath string) (*PhaseConfig, error) {
    // Read configuration file
    configData, err := os.ReadFile(configPath)
    if err != nil {
        return nil, fmt.Errorf("failed to read config file: %w", err)
    }
    
    // Parse JSON
    var config PhaseConfig
    if err := json.Unmarshal(configData, &config); err != nil {
        return nil, fmt.Errorf("failed to parse config JSON: %w", err)
    }
    
    // Validate configuration
    if err := validateConfig(config); err != nil {
        return nil, fmt.Errorf("invalid configuration: %w", err)
    }
    
    return &config, nil
}
```

## Implementation Guidance

### System Overview

The Conversation Phase Definition System provides a simple, configuration-driven approach to managing conversation flows. Key aspects include:

1. **File-Based Configuration**: Conversation structures defined in JSON files
2. **Simple Phase Structure**: Basic phase definitions with clear transitions
3. **Standard Format**: Common configuration format for consistency
4. **Basic Transitions**: Simple next-phase transitions
5. **Version Tracking**: Basic version information in configs

### How It Fits Into the Broader System

This component works as part of the Initial Assessment Call feature:

1. **Parent Feature**: Supports automated phone conversations with candidates

2. **Subfeature Relationships**: Works with other components:
   - SF002.2.2: Uses configs for conversation management
   - SF002.2.3: Uses phase definitions for information extraction
   - SF002.2.4: Uses basic error transitions
   - SF002.2.5: Uses phase timing information

3. **Information Flow**:
