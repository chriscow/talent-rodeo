# SF002.2.1: Conversation Phase Definition System

## Overview
The Conversation Phase Definition System serves as the state machine configuration for the conversation flow. It defines the valid states (phases), transitions, and requirements for each phase, providing a central source of truth that other components use to manage the conversation.

## Usage Example

### Configuration Example
```json
{
  "conversation_id": "initial_assessment",
  "version": "1.0",
  "phases": [
    {
      "id": "introduction",
      "name": "Introduction and Purpose",
      "prompt_template": "prompts/assessment/introduction.txt",
      "required_information": [
        { "key": "candidate_name", "type": "string", "required": true },
        { "key": "call_purpose_acknowledged", "type": "boolean", "required": true }
      ],
      "next_phase": "resume_verification",
      "max_duration": "3m"
    }
  ]
}
```

### Loading Configuration
```go
func loadPhaseConfiguration(configPath string) (*PhaseConfig, error) {
    // Read configuration file
    configData, err := os.ReadFile(configPath)
    if err != nil {
        return nil, fmt.Errorf("failed to read config file: %w", err)
    }
    
    // Parse JSON
    var config PhaseConfig
    if err := json.Unmarshal(configData, &config); err != nil {
        return nil, fmt.Errorf("failed to parse config JSON: %w", err)
    }
    
    // Validate configuration
    if err := validateConfig(config); err != nil {
        return nil, fmt.Errorf("invalid configuration: %w", err)
    }
    
    return &config, nil
}
```

## Implementation Guidance

### System Overview

The Conversation Phase Definition System provides a simple, configuration-driven approach to managing conversation flows. Key aspects include:

1. **File-Based Configuration**: Conversation structures defined in JSON files
2. **Simple Phase Structure**: Basic phase definitions with clear transitions
3. **Standard Format**: Common configuration format for consistency
4. **Basic Transitions**: Simple next-phase transitions
5. **Version Tracking**: Basic version information in configs

### How It Fits Into the Broader System

This component works as part of the Initial Assessment Call feature:

1. **Parent Feature**: Supports automated phone conversations with candidates

2. **Subfeature Relationships**: Works with other components:
   - SF002.2.2: Uses configs for conversation management
   - SF002.2.3: Uses phase definitions for information extraction
   - SF002.2.4: Uses basic error transitions
   - SF002.2.5: Uses phase timing information

3. **Information Flow**:
   - Configurations loaded at startup
   - Middleware uses configs for flow control
   - Information extraction guided by requirements
   - Time management follows phase limits
