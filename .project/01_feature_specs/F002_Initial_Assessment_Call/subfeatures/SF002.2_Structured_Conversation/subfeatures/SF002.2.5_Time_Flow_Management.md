# SF002.2.5: Time & Flow Management

## Overview
The Time & Flow Management subfeature ensures that assessment calls remain focused, efficient, and respectful of time constraints. It tracks conversation duration at both the overall and phase levels, adapts conversation pace to match time targets, and guides the flow toward high-priority information gathering when time is limited. This system ensures consistent, predictable call experiences with appropriate time allocation across conversation topics.

## Implementation Guidance

### System Overview

The Time & Flow Management component ensures assessment calls adhere to the required 15-20 minute duration while maintaining natural conversation flow. It acts as the "timekeeper" for the conversation, tracking progress and making strategic adjustments to ensure all critical information is collected within the time constraints.

Key aspects of this system include:

1. **Multi-Level Time Tracking**: Monitors time at the overall conversation, phase, and topic levels
2. **Adaptive Pacing**: Adjusts the conversation pace based on time progress and priorities
3. **Phase Transition Management**: Ensures appropriate time allocation across conversation phases
4. **Priority-Based Time Allocation**: Focuses remaining time on gathering the most critical information
5. **Graceful Conclusion**: Ensures conversations end appropriately within time constraints
6. **Time-Aware Communication**: Modifies system responses based on time conditions

### How It Works

The time management process follows these key steps:

1. **Time Tracking and Monitoring**: The system continuously tracks:
   - Overall elapsed and remaining conversation time
   - Time spent in each conversation phase compared to allocated time
   - Time spent on specific topics or information gathering
   - Turn-taking efficiency and patterns

2. **Time Allocation and Planning**: Based on conversation configuration, the system:
   ```
   Phase: Introduction         → 10% of time (1-3 minutes)
   Phase: Resume Verification  → 20% of time (2-5 minutes)
   Phase: Skills Assessment    → 40% of time (5-10 minutes)
   Phase: Preferences Gathering → 20% of time (2-5 minutes)
   Phase: Conclusion           → 10% of time (1-3 minutes)
   ```

3. **Pacing Guidance Generation**: The system analyzes timing data and generates appropriate pacing guidance for the LLM:
   ```
   TIME_INFO: Call duration: 8m30s elapsed (57%), 6m30s remaining. Phase 'skills_assessment': 3m15s elapsed (54%), 2m45s remaining.
   PACING: Maintain steady pace. Balance thoroughness with time awareness.
   ```

4. **Adjustment and Adaptation**: As time progresses, the system makes strategic adjustments:
   - When ahead of schedule: Encourages more detailed exploration
   - When on schedule: Maintains balanced information gathering
   - When behind schedule: Prioritizes essential information and reduces detail
   - When critically behind: Forces phase transitions and focuses only on critical data

5. **Time-Based Transitions**: When time thresholds are reached, the system:
   - Signals that the current phase should begin wrapping up
   - Prepares for transition to the next phase
   - Forces transitions when necessary to ensure overall call duration compliance

6. **Conclusion Management**: As the call approaches its end time:
   - Ensures smooth transition to conclusion phase with adequate time
   - Prioritizes final essential information collection
   - Manages graceful call termination

### How It Fits Into the Greater System

The Time & Flow Management component plays a critical role in the Structured Conversation feature:

1. **Integration with Phase Definition System (SF002.2.1)**: Uses phase configurations to determine time allocations and priorities for each conversation phase.

3. **Coordination with Information Extraction (SF002.2.3)**: Works with the information extraction system to prioritize gathering critical information when time is limited.

4. **Collaboration with Error Recovery (SF002.2.4)**: Works with error recovery to balance error handling with time constraints, potentially skipping complex recovery when time is critical.

5. **Connection to Telephony System (SF002.1)**: Ensures call durations match the scheduled appointment times and expected candidate experience.

This time management system provides several essential functions:

2. **Balanced Information Collection**: Allocates appropriate time to each conversation phase
3. **Complete Assessment Coverage**: Ensures all required information is collected before time runs out
4. **Natural Conversation Flow**: Maintains a natural pace while subtly managing time constraints

- Feel unnaturally paced with abrupt transitions

By continuously monitoring time and making strategic adjustments, this component creates a balance between thorough information gathering and time efficiency, resulting in a predictable, productive conversation experience.

## Usage Example

### TimeTracker Middleware Implementation

```go
type TimeTrackerMiddleware struct {
    startTime      time.Time
    maxDuration    time.Duration
    phaseStartTimes map[string]time.Time
    phaseAllocations map[string]time.Duration
    phaseConfig    *PhaseConfig
    phaseManager   *PhaseManagerMiddleware
    db             *sql.DB
    conversationID string
    mu             sync.RWMutex
}

func NewTimeTracker(db *sql.DB, conversationID string, maxDuration time.Duration, phaseConfig *PhaseConfig) *TimeTrackerMiddleware {
    // Calculate target durations for each phase based on percentages
    phaseAllocations := make(map[string]time.Duration)
    for _, phase := range phaseConfig.Phases {
        // Default allocation if not specified
        allocation := 0.2 // 20% of total time
        
        // Check if phase has specific time allocation
        for _, transition := range phase.Transitions {
            if transition.Type == "time_allocation" {
                allocation = transition.TimeAllocationPercentage
                break
            }
        }
        
        // Calculate duration
        phaseDuration := time.Duration(float64(maxDuration) * allocation)
        phaseAllocations[phase.ID] = phaseDuration
    }
    
    return &TimeTrackerMiddleware{
        startTime:       time.Now(),
        maxDuration:     maxDuration,
        phaseStartTimes: make(map[string]time.Time),
        phaseAllocations: phaseAllocations,
        phaseConfig:     phaseConfig,
        db:              db,
        conversationID:  conversationID,
    }
}

func (m *TimeTrackerMiddleware) SetPhaseManager(pm *PhaseManagerMiddleware) {
    m.phaseManager = pm
}

func (m *TimeTrackerMiddleware) Wrap(next minds.ThreadHandler) minds.ThreadHandler {
    return minds.ThreadHandlerFunc(func(tc minds.ThreadContext, _ minds.ThreadHandler) (minds.ThreadContext, error) {
        // Get current phase
        currentPhase := ""
        if m.phaseManager != nil {
            currentPhase = m.phaseManager.GetCurrentPhase()
        }
        
        // Track phase start time if this is a new phase
        m.mu.Lock()
        if _, exists := m.phaseStartTimes[currentPhase]; !exists && currentPhase != "" {
            m.phaseStartTimes[currentPhase] = time.Now()
        }
        m.mu.Unlock()
        
        // Calculate timing metrics
        elapsedTotal := time.Since(m.startTime)
        remainingTotal := m.maxDuration - elapsedTotal
        percentComplete := float64(elapsedTotal) / float64(m.maxDuration) * 100
        
        var elapsedPhase time.Duration
        var remainingPhase time.Duration
        var percentPhaseComplete float64
        
        if currentPhase != "" {
            m.mu.RLock()
            phaseStart, exists := m.phaseStartTimes[currentPhase]
            allocation := m.phaseAllocations[currentPhase]
            m.mu.RUnlock()
            
            if exists {
                elapsedPhase = time.Since(phaseStart)
                remainingPhase = allocation - elapsedPhase
                if allocation > 0 {
                    percentPhaseComplete = float64(elapsedPhase) / float64(allocation) * 100
                }
            }
        }
        
        // Determine pacing guidance based on timing
        var pacingGuidance string
        
        // Check if we're behind schedule overall
        if percentComplete > 90 && currentPhase != "conclusion" {
            // Critical time pressure - force transition to conclusion phase
            pacingGuidance = "CRITICAL TIME PRESSURE: Conversation is almost at maximum duration. Immediately transition to conclusion phase, skipping any remaining phases."
            
            // Force transition to conclusion if phase manager is available
            if m.phaseManager != nil {
                m.phaseManager.TransitionToPhase(tc, "conclusion")
            }
        } else if percentComplete > 75 && percentPhaseComplete > 100 {
            // Significant time pressure - force next phase
            pacingGuidance = "SIGNIFICANT TIME PRESSURE: Current phase is exceeding its allocation. Wrap up immediately and transition to next phase."
            
            // Force transition to next phase if phase manager is available
            if m.phaseManager != nil {
                m.phaseManager.TransitionToNextPhase(tc)
            }
        } else if percentComplete > 60 && percentPhaseComplete > 80 {
            // Moderate time pressure - expedite current phase
            pacingGuidance = "MODERATE TIME PRESSURE: Focus only on highest priority information in this phase. Use more directive questions and limit follow-ups."
        } else if percentComplete < 30 && percentPhaseComplete < 20 {
            // Ahead of schedule - can be more thorough
            pacingGuidance = "AHEAD OF SCHEDULE: There's time for additional detail. Ask follow-up questions and explore topics more thoroughly."
        } else {
            // On schedule - balanced pace
            pacingGuidance = "ON SCHEDULE: Maintain balanced pace. Continue with standard questioning approach."
        }
        
        // Create time information for the context
        timeInfo := fmt.Sprintf(
            "TIME_INFO: Call duration: %s elapsed (%.0f%%), %s remaining. Phase '%s': %s elapsed (%.0f%%), %s remaining.",
            formatDuration(elapsedTotal),
            percentComplete,
            formatDuration(remainingTotal),
            currentPhase,
            formatDuration(elapsedPhase),
            percentPhaseComplete,
            formatDuration(remainingPhase),
        )
        
        // Add time guidance to context for the LLM
        tc = tc.AppendMessages(minds.Message{
            Role: minds.RoleSystem,
            Content: timeInfo + "\nPACING: " + pacingGuidance,
        })
        
        // Log timing metrics
        m.logTimingMetrics(elapsedTotal, elapsedPhase, currentPhase)
        
        // Continue the middleware chain
        return next.HandleThread(tc, nil)
    })
}

func (m *TimeTrackerMiddleware) logTimingMetrics(totalElapsed, phaseElapsed time.Duration, phaseID string) {
    if phaseID == "" {
        return
    }
    
    _, err := m.db.Exec(`
        INSERT INTO conversation_timing_metrics (
            conversation_id, phase_id, start_time, duration_seconds, expected_duration_seconds
        ) VALUES (?, ?, ?, ?, ?)`,
        m.conversationID,
        phaseID,
        m.phaseStartTimes[phaseID],
        int(phaseElapsed.Seconds()),
        int(m.phaseAllocations[phaseID].Seconds()),
    )
    
    if err != nil {
        log.Printf("Failed to log timing metrics: %v", err)
    }
}

// Helper function to format durations in a user-friendly way
func formatDuration(d time.Duration) string {
    minutes := int(d.Minutes())
    seconds := int(d.Seconds()) % 60
    return fmt.Sprintf("%dm%02ds", minutes, seconds)
}
```

1. Track overall conversation time and phase-specific timings

5. Log timing metrics for analysis and improvement

The middleware integrates with the phase manager to understand the current conversation phase and to trigger phase transitions when necessary, working within the broader middleware framework to maintain efficient conversations that respect the 15-20 minute time constraint.
