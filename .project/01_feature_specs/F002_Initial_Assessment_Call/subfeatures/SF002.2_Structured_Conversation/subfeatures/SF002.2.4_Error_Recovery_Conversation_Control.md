# SF002.2.4: Error Recovery & Conversation Control

## Overview
The Error Recovery & Conversation Control subfeature enables the system to detect, handle, and recover from various conversation errors and unexpected situations, ensuring that assessment calls remain productive and on-track despite potential disruptions. It implements fallback strategies, redirection techniques, and graceful error handling to maintain a natural conversation flow even when challenges arise.

3. Customize fallback strategies based on:

## Implementation Guidance

### System Overview

The Error Recovery & Conversation Control component acts as a safety net for the conversation system, detecting and handling various types of problems that can occur during candidate assessment calls. It ensures conversations stay productive and on track, even when unexpected situations arise.

Key aspects of this system include:

1. **Error Detection**: Identifies different types of conversation issues in real-time
2. **Tiered Response System**: Implements increasingly assertive strategies based on error severity and frequency
3. **Graceful Recovery**: Maintains natural conversation flow even during recovery
4. **Threshold Management**: Tracks error patterns and escalates responses when needed
5. **Conversation Steering**: Guides conversations back to productive paths
6. **Phase Integration**: Works with phase transitions to ensure critical information is collected

### How It Works

The error recovery process follows these key steps:

1. **Monitoring and Detection**: The system constantly monitors the conversation for potential issues:
   - Candidate responses that are too brief or vague
   - Responses that are irrelevant to the current topic
   - Signs of confusion or misunderstanding
   - Technical issues like poor audio quality
   - Inappropriate or problematic content

2. **Error Classification**: When an issue is detected, it's classified by type and severity:
   ```
   Candidate: "Um, I'm not sure what you're asking."
   Error Type: "confusion"
   Severity: "low"
   ```

3. **Fallback Selection**: The system selects an appropriate fallback strategy based on:
   - Error type and severity
   - Number of similar errors in the current phase
   - Current conversation phase and goals
   - Time constraints and information gathering priorities

4. **Response Generation**: The system injects guidance into the LLM context:
   ```
   System: "Apply clarification strategy: Rephrase the question in simpler terms and provide an example."
   ```

5. **Threshold Management**: The system tracks error frequency and escalates responses when thresholds are exceeded:
   - First occurrence: Simple clarification
   - Second occurrence: More direct redirection
   - Third occurrence: Consider phase transition to more productive topics

6. **Recovery Monitoring**: The system monitors whether recovery was successful and resets error counts after successful interactions.

## Usage Example

### Error Recovery Middleware Implementation

```go
type ErrorRecoveryMiddleware struct {
    errorCounts    map[string]int // Error type -> count
    phaseManager   *PhaseManagerMiddleware
    maxErrorThreshold int
    db             *sql.DB
    conversationID string
    mu            sync.RWMutex
}

func NewErrorRecovery(db *sql.DB, conversationID string, maxErrors int) *ErrorRecoveryMiddleware {
    return &ErrorRecoveryMiddleware{
        errorCounts:      make(map[string]int),
        maxErrorThreshold: maxErrors,
        db:               db,
        conversationID:   conversationID,
    }
}

func (m *ErrorRecoveryMiddleware) SetPhaseManager(pm *PhaseManagerMiddleware) {
    m.phaseManager = pm
}

func (m *ErrorRecoveryMiddleware) Wrap(next minds.ThreadHandler) minds.ThreadHandler {
    return minds.ThreadHandlerFunc(func(tc minds.ThreadContext, _ minds.ThreadHandler) (minds.ThreadContext, error) {
        // Only analyze candidate messages
        messages := tc.Messages()
        if len(messages) == 0 {
            return next.HandleThread(tc, nil)
        }
        
        lastMsg := messages[len(messages)-1]
        if lastMsg.Role != "user" {
            return next.HandleThread(tc, nil)
        }
        
        // Check for errors in the response
        errorType := m.detectErrorType(lastMsg.Content, tc)
        if errorType == "" {
            // No error detected, reset counts for some error types after successful exchanges
            m.resetErrorCountsAfterSuccess()
            return next.HandleThread(tc, nil)
        }
        
        // Increment error count
        m.mu.Lock()
        m.errorCounts[errorType]++
        currentCount := m.errorCounts[errorType]
        m.mu.Unlock()
        
        // Log the error
        m.logError(errorType, lastMsg.Content, currentCount)
        
        // Select and apply fallback strategy
        fallbackMessage := m.selectFallbackStrategy(errorType, currentCount, tc)
        
        // Check thresholds and escalate if needed
        if currentCount >= m.maxErrorThreshold {
            // Major issue - try phase transition if multiple errors
            if m.phaseManager != nil {
                currentPhase := m.phaseManager.GetCurrentPhase()
                tc = tc.AppendMessages(minds.Message{
                    Role: minds.RoleSystem,
                    Content: fmt.Sprintf("Error threshold reached. Multiple %s errors detected. Transition from phase '%s' to next phase.", errorType, currentPhase),
                })
                m.phaseManager.TransitionToNextPhase(tc)
                
                // Reset count for this error type
                m.mu.Lock()
                m.errorCounts[errorType] = 0
                m.mu.Unlock()
            }
        } else {
            // Add guidance for the LLM on how to handle this error
            tc = tc.AppendMessages(minds.Message{
                Role: minds.RoleSystem,
                Content: fallbackMessage,
            })
        }
        
        // Continue the middleware chain
        return next.HandleThread(tc, nil)
    })
}

        return "brief_response"

    // 2. Check for confusion indicators
    confusionPhrases := []string{"i don't understand", "what do you mean", "not sure what", "confused"}
    for _, phrase := range confusionPhrases {
        if strings.Contains(strings.ToLower(message), phrase) {
            return "confusion"
        }
    }
    
    // 3. Check for relevance to current phase by getting expected topics
    // This would typically use an LLM to evaluate relevance
    
    // 4. Additional checks would be implemented for other error types
    
    return "" // No error detected
}

func (m *ErrorRecoveryMiddleware) selectFallbackStrategy(errorType string, count int, tc minds.ThreadContext) string {
    switch errorType {
    case "brief_response":
        if count == 1 {
            return "The candidate provided a very brief response. Ask a follow-up question to get more detail, using a friendly, encouraging tone."
        } else {
            return "The candidate consistently provides brief responses. Try a different approach - ask a specific question about their experience that requires a detailed answer."
        }
        
    case "confusion":
        if count == 1 {
            return "The candidate seems confused. Rephrase your question using simpler language and provide a clear example to illustrate what you're asking."
        } else {
            return "The candidate is still confused. Take a step back and explain the purpose of this line of questioning, then ask a more straightforward version of your question."
        }
        
    // Additional strategies for other error types
        
    default:
        return "There seems to be an issue with the conversation flow. Redirect to a related topic that might be more productive."
    }
}

func (m *ErrorRecoveryMiddleware) resetErrorCountsAfterSuccess() {
    m.mu.Lock()
    defer m.mu.Unlock()
    
    // Reset certain error types after successful exchanges
    // This allows recovery from temporary issues
    m.errorCounts["brief_response"] = 0
    m.errorCounts["confusion"] = 0
    
    // Some error types might not reset easily
    // For example, "off_topic" might indicate a persistent issue
}

func (m *ErrorRecoveryMiddleware) logError(errorType, message string, count int) {
    _, err := m.db.Exec(`
        INSERT INTO conversation_errors (conversation_id, error_type_id, error_context, created_at)
        VALUES (?, ?, ?, ?)`,
        m.conversationID, errorType, message, time.Now(),
    )
    if err != nil {
        log.Printf("Failed to log conversation error: %v", err)
    }
}
