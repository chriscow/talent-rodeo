# T003a.3.3: Update LLM Handlers to Persist Extracted Data

## Description
Modify the existing LLM handlers to store extracted data in the database after successful processing. This task connects the extraction handlers to the database persistence layer.

## Implementation Status
- [ ] Not Started

## Implementation Steps
1. Update the following handlers:
   - `RequirementsHandler`: Store extracted requirements in database
   - `WorkplaceHandler`: Store workplace details in database
   - `CultureHandler`: Store culture information in database
2. Modify the handler processing logic to call the new database methods after successful LLM extraction

## Acceptance Criteria
- Handlers successfully call database methods after extracting data
- Error handling correctly manages database failures
- Proper logging of storage operations
- Transactions used where appropriate for data consistency
- Unit tests verify database operations are called

## Example Implementation
```go
// In RequirementsHandler
func (h *RequirementsHandler) ProcessMessage(ctx context.Context, msg *jetstream.Msg, data interface{}) error {
    // Existing LLM processing
    // ...
    
    // New code to store results
    if err := h.db.SaveExtractedJobDetails(ctx, extractedDetails); err != nil {
        h.logger.Error("failed to store extracted job details", 
            "error", err, 
            "job_id", jobID)
        return fmt.Errorf("failed to store extracted job details: %w", err)
    }
    
    // Store extracted skills
    if err := h.db.SaveJobSkills(ctx, jobID, extractedSkills); err != nil {
        h.logger.Error("failed to store job skills", 
            "error", err, 
            "job_id", jobID)
        return fmt.Errorf("failed to store job skills: %w", err)
    }
    
    return nil
}
```
