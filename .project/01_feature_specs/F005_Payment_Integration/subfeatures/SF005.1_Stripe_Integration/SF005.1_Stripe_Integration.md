# SF005.1: Stripe Integration

## Overview
This subfeature implements payment processing for Talent Rodeo using Stripe Checkout as the payment service provider. It will enable candidates to make one-time payments for premium services that grant access for a predefined period.

## User Stories
- As a candidate, I want to purchase premium services using my credit card
- As a candidate, I want to see my current premium status and expiration date
- As a candidate, I want to receive email receipts for my purchases
- As an administrator, I want to track payment success rates and revenue

## Requirements

### Stripe Account Integration
- Set up a Stripe account for the application
- Configure webhook endpoints for critical payment status updates
- Implement secure API key management using environment variables
- Support both test and production environments

### Payment Processing
- Support one-time payments for premium access
- Handle payment confirmations and failures
- Store basic payment records in the database
- Utilize Stripe's built-in receipt email functionality

### Payment UI
- Utilize Stripe Checkout for a secure, pre-built payment form
- Display pricing information clearly
- Redirect users back to the application after payment
- Show confirmation of successful payments

### Access Period Management
- Update the user's subscription_end_date after successful payment
- Check subscription_end_date to determine premium access status
- Display remaining premium access time to users

### Critical Stripe Events for MVP
- Configure the webhook endpoint to listen for these specific events:
  1. `payment_intent.succeeded` - Triggered when a payment is successful
     - Required action: Update subscription_end_date, record payment, update tier
  2. `payment_intent.payment_failed` - Triggered when a payment attempt fails
     - Required action: Log failure, provide user feedback
  3. `checkout.session.completed` - Triggered when checkout process completes
     - Required action: Verify payment status, prepare for payment processing
- All other events can be ignored for the MVP implementation
- Events should be processed idempotently to prevent duplicate processing

### Error Handling Strategy
#### Internal Error Handling
- Implement structured logging for all payment-related operations
- Classify errors into specific categories:
  1. Payment processing errors (card declined, insufficient funds)
  2. Configuration errors (invalid API keys, misconfiguration)
  3. Network/connectivity errors (timeouts, connection issues)
  4. Webhook validation errors (signature verification failures)
- Implement monitoring and alerting for critical payment failures
- Track payment conversion rates and error patterns

#### User-Facing Error Communication
- Display specific, actionable error messages for payment form errors
- Create dedicated payment failure pages with clear instructions
- Implement asynchronous notifications for payment status changes
- Provide reference IDs for support inquiries on error pages
- Define user-friendly error messages for common payment issues

### Webhook Implementation Requirements
- Create a dedicated webhook endpoint to receive Stripe events
- Implement verification of webhook signatures to ensure security
- Handle critical payment events (payment_intent.succeeded, payment_intent.payment_failed)
- Process events asynchronously for scalability
- Implement idempotent event handling to prevent duplicate processing
- Return 2xx responses immediately before processing complex logic
- Configure proper retries for webhook delivery failures

### Security Considerations
- Ensure PCI compliance by using Stripe Checkout
- Never handle or store credit card information
- Implement HTTPS for all payment-related pages
- Use Stripe's built-in fraud detection
- Log all payment attempts for auditing purposes
- Verify webhook signatures to prevent tampering
- Exempt webhook routes from CSRF protection
- Configure TLS v1.2 or higher for webhook endpoints
- Roll webhook signing secrets periodically
- Implement protection against replay attacks using timestamp validation

### Payment Error Handling
```go
// PaymentError structure for consistent error handling
type PaymentError struct {
    Type        string // "card_error", "validation_error", "api_error", etc.
    Code        string // Specific error code from Stripe
    Message     string // Internal error message
    UserMessage string // User-friendly message
    Retryable   bool   // Whether the error can be retried
}

// Error handler method
func HandleStripeError(err error) *PaymentError {
    var stripeErr *stripe.Error
    if errors.As(err, &stripeErr) {
        // Handle Stripe-specific errors
        switch stripeErr.Type {
        case stripe.ErrorTypeCard:
            return &PaymentError{
                Type:        "card_error",
                Code:        stripeErr.Code,
                Message:     stripeErr.Message,
                UserMessage: getUserFriendlyCardErrorMessage(stripeErr.Code),
                Retryable:   true,
            }
        case stripe.ErrorTypeInvalidRequest:
            return &PaymentError{
                Type:        "validation_error",
                Code:        stripeErr.Code,
                Message:     stripeErr.Message,
                UserMessage: "There was a problem with your payment information. Please check your details and try again.",
                Retryable:   true,
            }
        // Handle other Stripe error types
        default:
            return &PaymentError{
                Type:        "api_error",
                Code:        stripeErr.Code,
                Message:     stripeErr.Message,
                UserMessage: "We're experiencing technical difficulties processing your payment. Please try again later.",
                Retryable:   false,
            }
        }
    }
    
    // Handle non-Stripe errors
    return &PaymentError{
        Type:        "system_error",
        Message:     err.Error(),
        UserMessage: "An unexpected error occurred. Please try again later.",
        Retryable:   false,
    }
}

// Get user-friendly message for card errors
func getUserFriendlyCardErrorMessage(code string) string {
    messages := map[string]string{
        "card_declined":                 "Your card was declined. Please try another payment method.",
        "expired_card":                  "Your card has expired. Please use a different card.",
        "incorrect_cvc":                 "The security code (CVC) is incorrect. Please check your card details.",
        "insufficient_funds":            "Your card has insufficient funds. Please use a different payment method.",
        "invalid_expiry_month":          "The expiration month is invalid. Please check your card details.",
        "invalid_expiry_year":           "The expiration year is invalid. Please check your card details.",
        "invalid_number":                "The card number is invalid. Please check your card details.",
        "processing_error":              "An error occurred while processing your card. Please try again.",
    }
    
    if msg, ok := messages[code]; ok {
        return msg
    }
    
    return "There was a problem processing your card. Please try again with a different payment method."
}
```

### Service Integration
The Stripe integration service will handle payment processing and webhook events. It will interact with the Stripe API using the official Go library and focus on one-time payments through Stripe Checkout.

### Stripe Checkout Integration Flow
1. User clicks "Upgrade" button
2. Server creates a Stripe Checkout session
3. User is redirected to Stripe Checkout page
4. User completes payment on Stripe's servers
5. Stripe redirects user back to success or cancel URL
6. Webhook receives payment confirmation and updates user status

### Webhook Handler Implementation in Go
```go
// Webhook endpoint handler
func (s *StripeService) WebhookHandler() http.HandlerFunc {
    return func(w http.ResponseWriter, req *http.Request) {
        const MaxBodyBytes = int64(65536)
        req.Body = http.MaxBytesReader(w, req.Body, MaxBodyBytes)
        payload, err := ioutil.ReadAll(req.Body)
        if err != nil {
            log.Printf("Error reading request body: %v\n", err)
            w.WriteHeader(http.StatusServiceUnavailable)
            return
        }

        // Get the signature from the header
        sigHeader := req.Header.Get("Stripe-Signature")
        
        // Verify webhook signature
        event, err := webhook.ConstructEvent(payload, sigHeader, s.config.WebhookSecret)
        if err != nil {
            log.Printf("Error verifying webhook signature: %v\n", err)
            w.WriteHeader(http.StatusBadRequest)
            return
        }

        // Immediately return a 200 response before processing
        // This prevents timeouts and unnecessary retries
        w.WriteHeader(http.StatusOK)
        
        // Process the event asynchronously (non-blocking)
        go s.processWebhookEvent(event)
    }
}

// Process webhook event asynchronously
func (s *StripeService) processWebhookEvent(event stripe.Event) {
    // Check if we've already processed this event
    var count int
    err := s.db.QueryRow("SELECT COUNT(*) FROM stripe_events WHERE id = $1", event.ID).Scan(&count)
    if err != nil {
        log.Printf("Error checking if event was processed: %v\n", err)
        return
    }
    
    if count > 0 {
        // Event already processed, skip
        log.Printf("Event %s already processed, skipping\n", event.ID)
        return
    }
    
    // Handle the event based on type
    switch event.Type {
    case "payment_intent.succeeded":
        var paymentIntent stripe.PaymentIntent
        err := json.Unmarshal(event.Data.Raw, &paymentIntent)
        if err != nil {
            log.Printf("Error parsing payment intent: %v\n", err)
            return
        }
        s.handlePaymentIntentSucceeded(paymentIntent)
        
    case "payment_intent.payment_failed":
        var paymentIntent stripe.PaymentIntent
        err := json.Unmarshal(event.Data.Raw, &paymentIntent)
        if err != nil {
            log.Printf("Error parsing payment intent: %v\n", err)
            return
        }
        s.handlePaymentIntentFailed(paymentIntent)
        
    case "checkout.session.completed":
        var session stripe.CheckoutSession
        err := json.Unmarshal(event.Data.Raw, &session)
        if err != nil {
            log.Printf("Error parsing checkout session: %v\n", err)
            return
        }
        s.handleCheckoutSessionCompleted(session)
        
    default:
        log.Printf("Unhandled event type: %s\n", event.Type)
    }
    
    // Record that we processed this event to prevent duplicates
    _, err = s.db.Exec("INSERT INTO stripe_events (id, type) VALUES ($1, $2)", event.ID, event.Type)
    if err != nil {
        log.Printf("Error recording processed event: %v\n", err)
    }
}

// Handle successful payment
func (s *StripeService) handlePaymentIntentSucceeded(paymentIntent stripe.PaymentIntent) {
    // Extract customer ID from metadata
    candidateID, ok := paymentIntent.Metadata["candidate_id"]
    if !ok {
        log.Printf("Payment intent %s has no candidate_id in metadata\n", paymentIntent.ID)
        return
    }
    
    // Record the payment in the database
    _, err := s.db.Exec(
        "INSERT INTO payments (candidate_id, stripe_payment_id, amount, currency, status) VALUES ($1, $2, $3, $4, $5)",
        candidateID,
        paymentIntent.ID,
        float64(paymentIntent.Amount) / 100.0, // Convert from cents
        strings.ToLower(string(paymentIntent.Currency)),
        "succeeded",
    )
    if err != nil {
        log.Printf("Error recording payment: %v\n", err)
        return
    }
    
    // Update subscription_end_date (30 days from now)
    subscriptionEndDate := time.Now().AddDate(0, 0, 30)
    _, err = s.db.Exec(
        "UPDATE candidates SET tier = 'mid', subscription_end_date = $1 WHERE id = $2",
        subscriptionEndDate,
        candidateID,
    )
    if err != nil {
        log.Printf("Error updating subscription: %v\n", err)
        return
    }
    
    log.Printf("Successfully processed payment and updated subscription for candidate %s\n", candidateID)
}

// Handle failed payment
func (s *StripeService) handlePaymentIntentFailed(paymentIntent stripe.PaymentIntent) {
    // Extract customer ID from metadata
    candidateID, ok := paymentIntent.Metadata["candidate_id"]
    if !ok {
        log.Printf("Payment intent %s has no candidate_id in metadata\n", paymentIntent.ID)
        return
    }
    
    // Record the failed payment
    _, err := s.db.Exec(
        "INSERT INTO payments (candidate_id, stripe_payment_id, amount, currency, status) VALUES ($1, $2, $3, $4, $5)",
        candidateID,
        paymentIntent.ID,
        float64(paymentIntent.Amount) / 100.0,
        strings.ToLower(string(paymentIntent.Currency)),
        "failed",
    )
    if err != nil {
        log.Printf("Error recording failed payment: %v\n", err)
        return
    }
    
    // Log the payment error
    errorMessage := "Unknown error"
    if paymentIntent.LastPaymentError != nil {
        errorMessage = paymentIntent.LastPaymentError.Message
    }
    
    _, err = s.db.Exec(
        "INSERT INTO payment_errors (candidate_id, stripe_payment_id, error_type, error_message) VALUES ($1, $2, $3, $4)",
        candidateID,
        paymentIntent.ID,
        "payment_failed",
        errorMessage,
    )
    if err != nil {
        log.Printf("Error logging payment error: %v\n", err)
    }
    
    log.Printf("Payment failed for candidate %s: %s\n", candidateID, errorMessage)
}
```

## Webhook Security Best Practices
1. Verify webhook signatures to ensure requests come from Stripe
2. Process events idempotently to handle duplicate events
3. Return 2xx response quickly before performing complex operations
4. Store processed event IDs to prevent duplicate processing
5. Handle events asynchronously for better performance
6. Check timestamp in Stripe-Signature header to prevent replay attacks
7. Keep webhook endpoint URL and secret secure
8. Only subscribe to event types that your application needs
9. Exempt webhook endpoints from CSRF protection in your web framework
10. Use HTTPS for all webhook endpoints
