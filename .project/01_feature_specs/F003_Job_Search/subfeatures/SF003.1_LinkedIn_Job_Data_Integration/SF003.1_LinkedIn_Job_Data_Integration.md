# SF003.1: LinkedIn Job Data Integration

## Overview
The LinkedIn Job Data Integration subfeature enables Talent Rodeo to access and utilize job listings from LinkedIn through the ScrapingDog API. This integration provides access to current, relevant job postings from one of the largest professional networks, supporting the job search process.

## Implementation Status
**Partially Implemented**

## Detailed Requirements

### API Integration
1. Implement ScrapingDog API client for LinkedIn job searches
2. Support authentication and authorization with the ScrapingDog service
3. Handle rate limiting and usage quotas
4. Implement error handling for API failures and timeouts

### Data Retrieval
1. Support pagination for comprehensive job listing retrieval
2. Implement query construction based on user skills and preferences
3. Support filtering by location, experience level, and job type
4. Extract relevant job details from the API response

### Cache Management
1. Implement a caching layer to minimize redundant API calls
2. Set appropriate cache expiration policies
3. Support cache invalidation for refreshing stale data
4. Implement background job refreshing for popular searches

### Error Handling
1. Gracefully handle API unavailability
2. Implement fallback mechanisms when API limits are reached
3. Log detailed error information for monitoring
4. Provide user-friendly error messages when search fails

### Data Normalization
1. Process raw job data into standardized format
2. Clean and normalize job titles for consistent searching
3. Extract and structure skills from job descriptions
4. Standardize location information for geographic queries
5. Handle duplicate job listings from different search queries

## User Experience
- Users should not perceive delays due to external API calls
- Search results should appear relevant to the user's profile
- Failed searches should provide clear feedback and alternatives
- Users should be able to refine search parameters if initial results are unsatisfactory

## Database Schema References
```sql
-- job_listings table stores job listings retrieved from LinkedIn
CREATE TABLE IF NOT EXISTS job_listings (
    id SERIAL PRIMARY KEY,
    external_id TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    company TEXT NOT NULL,
    location TEXT,
    description TEXT,
    url TEXT NOT NULL,
    posted_date TIMESTAMP,
    source TEXT NOT NULL DEFAULT 'linkedin',
    search_query TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- job_searches table for storing search queries and parameters
CREATE TABLE IF NOT EXISTS job_searches (
    id SERIAL PRIMARY KEY,
    query_hash TEXT NOT NULL UNIQUE,
    query_text TEXT NOT NULL,
    search_params JSONB NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP NOT NULL
);

-- search_results table for mapping searches to job results
CREATE TABLE IF NOT EXISTS search_results (
    id SERIAL PRIMARY KEY,
    search_id INTEGER NOT NULL REFERENCES job_searches(id),
    job_id INTEGER NOT NULL REFERENCES job_listings(id),
    result_order INTEGER NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (search_id, job_id)
);
```

### Cache Implementation
```go
// Sample code for cache implementation
func (c *Cache) GetJobResults(query string) (*JobResults, bool) {
    queryHash := hash(query)
    
    c.mu.RLock()
    cachedResult, found := c.items[queryHash]
    c.mu.RUnlock()
    
    if !found || cachedResult.ExpiresAt.Before(time.Now()) {
        return nil, false
    }
    
    return cachedResult.Results, true
}
```
