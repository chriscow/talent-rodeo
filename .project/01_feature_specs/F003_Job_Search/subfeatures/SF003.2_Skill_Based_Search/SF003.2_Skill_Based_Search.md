# SF003.2: Skill-Based Search

## Overview
The Skill-Based Search subfeature enables Talent Rodeo to conduct targeted job searches based on the skills identified during candidate onboarding and assessment processes. This ensures that search results align with the candidate's technical capabilities and experience, increasing the relevance of job opportunities presented.

## Implementation Status
**Implemented**

## Detailed Requirements

### Skill Extraction
1. Extract skills from candidate profiles and assessment results
2. Categorize skills into "must-have" and "preferred" categories
3. Identify skill proficiency levels where available
4. Recognize variations and synonyms of common skills
5. Maintain a database of skill relationships and equivalencies

### Query Construction
1. Build optimized search queries based on candidate skill profiles
2. Prioritize "must-have" skills in query construction
3. Include secondary "preferred" skills with appropriate weighting
4. Support variations in skill terminology and industry-specific naming
5. Employ structured query building for optimal results
6. Implement query generalization for overly specific skill sets

### Search Execution
1. Execute searches against job data sources
2. Support multiple simultaneous searches with different skill combinations
3. Track search performance and result quality
4. Adapt search strategies based on result quality metrics
5. Implement fallback strategies for low-result searches

### Search Caching
1. Cache search results for performance optimization
2. Implement cache invalidation strategies
3. Support partial cache updates when new jobs are available
4. Track cache hit/miss metrics for optimization
5. Prioritize cache refreshes based on user activity

## User Experience
- Users should see job results that align with their core skills
- Search results should highlight which user skills were matched
- The system should handle both technical and soft skills appropriately
- UI should provide feedback when skills are too specific or rare
- Search interface should allow manual adjustment of skill importance

## Database Schema References
```sql
-- candidate_skills table stores skills extracted from candidate profiles
CREATE TABLE IF NOT EXISTS candidate_skills (
    id SERIAL PRIMARY KEY,
    candidate_id INTEGER NOT NULL REFERENCES candidates(id),
    skill TEXT NOT NULL,
    importance VARCHAR(20) NOT NULL DEFAULT 'preferred', -- 'must-have' or 'preferred'
    proficiency INTEGER,
    source VARCHAR(50) NOT NULL, -- 'resume', 'assessment', 'profile', etc.
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (candidate_id, skill)
);

-- skill_relationships table for managing skill synonyms and relationships
CREATE TABLE IF NOT EXISTS skill_relationships (
    id SERIAL PRIMARY KEY,
    skill_a TEXT NOT NULL,
    skill_b TEXT NOT NULL,
    relationship_type VARCHAR(20) NOT NULL, -- 'synonym', 'parent', 'child', etc.
    confidence FLOAT NOT NULL DEFAULT 1.0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (skill_a, skill_b, relationship_type)
);

-- search_skill_mappings table for tracking which skills were used in searches
CREATE TABLE IF NOT EXISTS search_skill_mappings (
    id SERIAL PRIMARY KEY,
    search_id INTEGER NOT NULL REFERENCES job_searches(id),
    skill TEXT NOT NULL,
    importance VARCHAR(20) NOT NULL, -- 'must-have' or 'preferred'
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE (search_id, skill)
);
```

### Query Building Example
```go
// Sample code for query building
func BuildSearchQuery(skills []Skill) *SearchQuery {
    query := NewSearchQuery()
    
    // Add must-have skills
    for _, skill := range filterSkillsByImportance(skills, "must-have") {
        query.AddMustHaveSkill(skill.Name)
        
        // Add synonyms
        for _, synonym := range getSkillSynonyms(skill.Name) {
            query.AddMustHaveSkillSynonym(synonym)
        }
    }
    
    // Add preferred skills with lower weight
    for _, skill := range filterSkillsByImportance(skills, "preferred") {
        query.AddPreferredSkill(skill.Name)
    }
    
    return query.Optimize()
}
```
