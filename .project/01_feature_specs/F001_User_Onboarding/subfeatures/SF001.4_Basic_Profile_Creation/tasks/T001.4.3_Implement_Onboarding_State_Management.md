# T001.4.3: Implement Onboarding State Management

## Description
Implement a comprehensive onboarding state management system that tracks user progress through the onboarding process, enforces the correct flow between steps, and provides appropriate redirects based on current state. This system will ensure that users follow the intended onboarding path while allowing for flexible navigation where appropriate.

## Implementation Details

### Onboarding State Definition
- Define enumerated states for the onboarding process:
  - `initial`: Account created, needs to upload resume
  - `resume_uploaded`: Resume uploaded, needs to schedule phone call
  - `phone_call_scheduled`: Call scheduled, waiting for call
  - `phone_call_completed`: Call finished, extracting preferences
  - `preferences_extracted`: Preferences established from call
  - `job_search_started`: Initial job search performed
  - `complete`: Full onboarding process completed
- Create a type system and constants for these states
- Document transitions between states
- Define helper functions for state operations

### State Persistence
- Create database functions to update onboarding state
- Store timestamps for each state transition
- Track overall onboarding start and completion times
- Ensure atomic updates to maintain data integrity

### Flow Control
- Implement middleware to check current onboarding state
- Create route guards based on required states
- Implement appropriate redirects based on current state
- Handle direct URL access to pages out of sequence

### User Experience
- Provide clear indication of current onboarding progress
- Implement visual progress indicators based on state
- Show appropriate next steps based on current state
- Support resuming the onboarding process from the last completed step

## Acceptance Criteria
- Onboarding states are correctly defined and documented
- State transitions occur properly during the onboarding flow
- Database updates include appropriate timestamps
- Users are redirected to the correct page based on their state
- Access to pages is appropriately restricted based on state
- Visual indicators properly reflect the current onboarding progress
- The system handles edge cases like users trying to skip steps

## Dependencies
- Database schema with onboarding state fields
- User authentication and session management
- HTTP routing system for redirects
- Template system for visual indicators

### State Definitions

```go
// In internal/onboarding/types.go
package onboarding

import "time"

// Step represents the current step in the user onboarding process
type Step string

const (
    // StepInitial is the starting state
    StepInitial Step = "initial"

    // StepResumeUploaded indicates the resume has been uploaded and processed
    StepResumeUploaded Step = "resume_uploaded"

    // StepPhoneCallScheduled indicates we've scheduled the phone call
    StepPhoneCallScheduled Step = "phone_call_scheduled"

    // StepPhoneCallCompleted indicates the phone call is done
    StepPhoneCallCompleted Step = "phone_call_completed"

    // StepPreferencesExtracted indicates we've processed the call and extracted preferences
    StepPreferencesExtracted Step = "preferences_extracted"

    // StepJobSearchStarted indicates we've begun searching for matching jobs
    StepJobSearchStarted Step = "job_search_started"

    // StepComplete indicates the full process is complete
    StepComplete Step = "complete"
)

// State contains all onboarding-related data for a user
type State struct {
    CurrentStep       Step       `db:"onboarding_step"`
    StartedAt         *time.Time `db:"onboarding_started_at"`
    CompletedAt       *time.Time `db:"onboarding_completed_at"`
    StepLastUpdatedAt *time.Time `db:"onboarding_step_updated_at"`
}

// NextStep returns the next logical step in the onboarding process
func (s *State) NextStep() Step {
    switch s.CurrentStep {
    case StepInitial:
        return StepResumeUploaded
    case StepResumeUploaded:
        return StepPhoneCallScheduled
    case StepPhoneCallScheduled:
        return StepPhoneCallCompleted
    case StepPhoneCallCompleted:
        return StepPreferencesExtracted
    case StepPreferencesExtracted:
        return StepJobSearchStarted
    case StepJobSearchStarted:
        return StepComplete
    default:
        return s.CurrentStep
    }
}
```

```go
// In internal/database/users.go
func (db *DB) UpdateOnboardingStep(userID int, step onboarding.Step) error {
    ctx, cancel := context.WithTimeout(context.Background(), defaultTimeout)
    defer cancel()

    now := time.Now()
    
    query := `
        UPDATE users 
        SET onboarding_step = $1, 
            onboarding_step_updated_at = $2,
            onboarding_started_at = COALESCE(onboarding_started_at, $2),
            onboarding_completed_at = CASE WHEN $1 = 'complete' THEN $2 ELSE onboarding_completed_at END,
            updated_at = $2
        WHERE id = $3
    `
    
    _, err := db.ExecContext(ctx, query, string(step), now, userID)
    return err
}

func (db *DB) GetUserOnboardingState(userID int) (*onboarding.State, error) {
    ctx, cancel := context.WithTimeout(context.Background(), defaultTimeout)
    defer cancel()
    
    var state onboarding.State
    query := `
        SELECT 
            onboarding_step, 
            onboarding_started_at, 
            onboarding_completed_at, 
            onboarding_step_updated_at
        FROM users 
        WHERE id = $1
    `
    
    err := db.GetContext(ctx, &state, query, userID)
    if err != nil {
        return nil, err
    }
    
    return &state, nil
}
```

### Route Guards
```go
// In cmd/web/middleware.go
func (app *application) requireOnboardingState(requiredState onboarding.Step, redirectMap map[onboarding.Step]string) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        user := contextGetAuthenticatedUser(r)
        if user == nil {
            http.Redirect(w, r, "/auth/login", http.StatusFound)
            return
        }
        
        if onboarding.Step(user.OnboardingStep) != requiredState {
            currentState := onboarding.Step(user.OnboardingStep)
            if redirectPath, exists := redirectMap[currentState]; exists {
                http.Redirect(w, r, redirectPath, http.StatusFound)
                return
            }
            
            // Default redirect to profile page
            http.Redirect(w, r, "/profile", http.StatusFound)
            return
        }
        
        // Continue processing the request
    }
}
```
