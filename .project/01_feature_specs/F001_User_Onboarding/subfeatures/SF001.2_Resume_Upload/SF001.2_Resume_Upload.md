# SF001.2: Resume Upload

## Overview
The Resume Upload subfeature enables users to upload their resume in standard document formats. The system processes these documents to extract text content, which is used to build the user's initial profile and later for job matching and document customization.

## Status
**Implemented**

## Detailed Requirements

### Upload Functionality
1. Present a simple, intuitive file upload interface for users
2. Accept PDF and DOCX format resumes
3. Validate file type before processing (using both extension and MIME type)
4. Enforce reasonable file size limits (recommend 5MB maximum)
5. Display progress indicator during upload
6. Provide clear success/failure feedback
7. Allow users to replace previously uploaded resumes

### File Processing
1. Store uploaded file temporarily for processing
2. Extract text content using appropriate parser:
   - For PDF: Use PDF text extraction library
   - For DOCX: Use DOCX parser library
3. Analyze extracted text for basic structure (sections, contact details, etc.)
4. Store extracted text in the database associated with the user's profile
5. Generate a summarized version of the resume for quick reference
6. Handle common extraction issues:
   - Scanned documents with no text layer
   - Unusual formatting/layouts
   - Special characters and encodings
   - Tables and multi-column layouts

### Phone Number Collection
1. Collect user's phone number via form input alongside resume upload
2. Validate phone number format (support international formats)
3. Store phone number in the user's profile
4. If phone number appears in resume, pre-fill form field (validation still required)
5. Compare provided phone with number in resume for basic validation

### Resume Data Storage
1. Store the full original resume text in the database
2. Create a summarized version focusing on key elements
3. Track the filename and upload timestamp
4. Associate all data with the correct user profile
5. Implement secure storage that prevents cross-user access

### Error Handling
1. Detect and report file type mismatches
2. Handle upload interruptions gracefully
3. Report extraction failures with appropriate error messages
4. Provide user-friendly messages for all error conditions
5. Log detailed errors for debugging purposes

## User Experience
1. Present a clean, simple upload interface
2. Provide clear instructions on acceptable file formats
3. Show progress indicator during upload and processing
4. Offer preview functionality after successful upload
5. Enable easy reupload if the user wishes to change their resume
6. Guide users to next steps after successful upload

## Test Cases
1. **Valid File Upload**: Verify successful upload and processing of PDF and DOCX files
2. **Invalid File Type**: Verify rejection of unsupported file types with appropriate error message
3. **Large File Handling**: Verify handling of files beyond size limits
4. **Resume Replacement**: Verify a user can replace an existing resume
5. **Text Extraction**: Verify accurate extraction of text content from various document layouts
6. **Phone Validation**: Verify phone number validation and storage

### Handler Pseudocode
```go
func handleResumeUpload(w http.ResponseWriter, r *http.Request) {
  // Get authenticated user
  user := getAuthenticatedUser(r)
  
  // Parse multipart form
  err := r.ParseMultipartForm(5 << 20) // 5MB max
  
  // Get phone number
  phone := r.FormValue("phone")
  
  // Validate phone format
  if !isValidPhoneNumber(phone) {
    renderError(w, "Invalid phone number format")
    return
  }
  
  // Get uploaded file
  file, header, err := r.FormFile("resume")
  
  // Validate file type
  if !isValidFileType(header.Filename) {
    renderError(w, "Invalid file type. Please upload PDF or DOCX files only.")
    return
  }
  
  // Extract text based on file type
  text := extractResumeText(file, header.Filename)
  
  // Generate summary
  summary := summarizeResume(text)
  
  // Update user profile
  updateUserResume(user.ID, header.Filename, text, summary, phone)
  
  // Update onboarding state
  updateOnboardingStep(user.ID, "resume_uploaded")
  
  // Redirect to next step
  http.Redirect(w, r, "/profile/schedule", http.StatusFound)
}
```
