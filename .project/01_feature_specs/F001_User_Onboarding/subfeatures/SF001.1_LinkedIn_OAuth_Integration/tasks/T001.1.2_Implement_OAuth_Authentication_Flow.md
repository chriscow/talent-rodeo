# T001.1.2: Implement OAuth Authentication Flow

## Task Description
Implement the OAuth authentication flow for LinkedIn authentication, handling the initiation of the OAuth process, callback handling, and error management. This task involves creating the necessary handlers and routes to manage the complete authentication lifecycle.

## Implementation Details

### Authentication Handlers
1. Implement the handler for initiating the LinkedIn authentication process:
   - Extract the provider from the URL path
   - Set up the request for the OAuth provider
   - Begin the OAuth flow redirecting to LinkedIn
   
2. Implement the callback handler for completing the authentication:
   - Process the callback from LinkedIn
   - Extract authorization code and exchange for access token
   - Handle errors from LinkedIn (denials, service unavailability)
   - Complete the user authentication process
   - Redirect to appropriate page based on authentication result

### Route Configuration
1. Set up the routes for the OAuth flow:
   - `/auth/linkedin` - For initiating the authentication process
   - `/auth/linkedin/callback` - For processing the OAuth callback
   
2. Ensure routes have appropriate middleware:
   - Anonymous user requirement for initiating authentication
   - CSRF protection for the OAuth flow

### Error Handling
1. Implement specific error handling for authentication failures:
   - Permission denials by the user
   - LinkedIn service unavailability
   - Invalid or expired authorization codes
   - Network connectivity issues
   
2. Create user-friendly error messages for each failure scenario
3. Implement appropriate logging for debugging authentication issues

## Acceptance Criteria
1. Users can initiate authentication by visiting `/auth/linkedin`
2. System correctly processes the callback from LinkedIn
3. Authentication errors are handled gracefully with clear user messages
4. CSRF protection is implemented for the OAuth flow
5. Appropriate logging occurs for debugging authentication issues

## Dependencies
- LinkedIn OAuth provider configuration (T001.1.1)
- HTTP router and middleware components
- Error handling utilities

### Code References
The authentication flow handlers should be implemented in `cmd/web/handlers.auth.go`:

```go
// Initiate authentication
func (app *application) startSocialAuth(w http.ResponseWriter, r *http.Request) {
    provider := flow.Param(r.Context(), "provider")
    q := r.URL.Query()
    q.Set("provider", provider)
    r.URL.RawQuery = q.Encode()

    gothic.BeginAuthHandler(w, r)
}

// Handle callback
func (app *application) completeSocialAuth(w http.ResponseWriter, r *http.Request) {
    // Check for errors in callback
    if r.URL.Query().Get("error") != "" {
        app.logger.Error("OAuth error",
            "error", r.URL.Query().Get("error"),
            "description", r.URL.Query().Get("error_description"))
        http.Error(w, "You must grant access to continue.", http.StatusUnauthorized)
        return
    }

    // Complete authentication process
    // ...
}
```

The route configuration should be added to `cmd/web/routes.go`:

```go
// Authentication routes
router.Get("/auth/:provider", app.startSocialAuth)
router.Get("/auth/:provider/callback", app.completeSocialAuth)
```
