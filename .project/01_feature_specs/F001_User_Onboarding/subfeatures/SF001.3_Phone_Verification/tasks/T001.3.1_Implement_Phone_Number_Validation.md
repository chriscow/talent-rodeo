# T001.3.1: Implement Phone Number Validation

## Description
Implement comprehensive phone number validation to ensure that users provide properly formatted phone numbers during the onboarding process. The validation should support both client-side and server-side validation with consistent rules and clear error messages.

## Implementation Details

### Validation Rules
- Implement regex patterns for validating phone numbers:
  - Support US/Canada formatted numbers (e.g., +1 (123) 456-7890)
  - Support international formats with country codes
  - Allow numbers with or without formatting characters (spaces, dashes, parentheses)
  - Minimum of 10 digits and maximum of 15 digits (including country code)
- Normalize phone numbers by removing formatting characters before validation
- Implement E.164 formatting (+12345678901) for consistent storage

### Client-Side Validation
- Add HTML5 validation attributes to phone input field:
  - Use `type="tel"` for appropriate mobile keyboard
  - Add `pattern` attribute with appropriate regex
  - Set `required` attribute
- Implement JavaScript validation for real-time feedback
- Show appropriate error messages for validation failures

### Server-Side Validation
- Create a validation function in the form validator package
- Implement the same validation rules on the server-side
- Return specific error messages for different validation failures
- Format phone numbers consistently before storing in the database

### Error Handling
- Create clear, user-friendly error messages for different validation issues
- Log validation failures with appropriate context
- Implement graceful error recovery allowing users to correct inputs

## Acceptance Criteria
- Valid phone numbers are accepted in multiple formats
- Invalid phone numbers are rejected with appropriate error messages
- Client-side validation provides immediate feedback to users
- Server-side validation ensures data integrity
- Phone numbers are consistently formatted before storage
- Users can correct and resubmit after validation failures
- The system handles edge cases like extensions and toll-free numbers appropriately

## Dependencies
- Form validation utilities
- HTML templates for user input
- Regular expression support
- Database operations for storing phone numbers

### Validation Code Example
```go
// Check if the phone number is valid
func isValidPhoneNumber(phone string) bool {
    // Strip all non-digit characters except leading +
    digitsOnly := regexp.MustCompile(`[^\d+]`).ReplaceAllString(phone, "")
    
    // Check if it starts with + followed by digits or just digits
    validFormat := regexp.MustCompile(`^\+?[1-9]\d{7,14}$`)
    return validFormat.MatchString(digitsOnly)
}

// Format phone number to E.164 format
func formatPhoneToE164(phone string) string {
    // Remove all non-digit characters
    digitsOnly := regexp.MustCompile(`[^\d+]`).ReplaceAllString(phone, "")
    
    // If it doesn't start with +, add +1 (assuming US/Canada)
    if !strings.HasPrefix(digitsOnly, "+") {
        if strings.HasPrefix(digitsOnly, "1") {
            digitsOnly = "+" + digitsOnly
        } else {
            digitsOnly = "+1" + digitsOnly
        }
    }
    
    return digitsOnly
}
```

// In form validation
phoneRegex := regexp.MustCompile(`^\+?1?\d{10,15}$`)
form.Validator.CheckField(validator.Matches(form.Phone, phoneRegex), "phone", "Invalid phone number format")

// In database update
func (db *DB) UpdateUserPhone(userID int, phone string) error {
    ctx, cancel := context.WithTimeout(context.Background(), defaultTimeout)
    defer cancel()

    // Format phone to E.164 before storage
    formattedPhone := formatPhoneToE164(phone)
    
    var phonePtr *string
    if formattedPhone != "" {
        phonePtr = &formattedPhone
    }

    query := `UPDATE users SET phone = $1 WHERE id = $2`
    _, err := db.ExecContext(ctx, query, phonePtr, userID)
    return err
}
