# SF001.3: Phone Verification

## Overview
The Phone Verification subfeature collects and validates a user's phone number during the onboarding process. This phone number is essential for later communication with the AI assistant for assessment calls and enables the system to establish a direct communication channel with the candidate.

## Status
**Implemented**

## Detailed Requirements

### Phone Collection
1. Present a clear, accessible form field for phone number entry
2. Collect phone number as part of the resume upload process
3. For the MVP, only support United States phone numbers. Support international phone number formats in the future.
4. Provide formatting guidance/examples to users
5. Clearly explain why the phone number is needed (for assessment calls)

### Validation Requirements
1. Validate phone number format on client-side before submission
2. Perform server-side validation to ensure proper format
3. Implement basic validation patterns that support:
   - US/Canada formatted numbers (e.g., +1 (123) 456-7890)
   - International formats with country codes (e.g., +44 7911 123456)
   - Numbers with or without formatting characters (spaces, dashes, parentheses)
4. Check for minimum and maximum length constraints (typically 10-15 digits)
5. Compare provided phone number with any number detected in the uploaded resume for basic verification
6. Allow resubmission if validation fails

### Data Storage
1. Store the validated phone number in the users table
2. Format the number consistently before storage (e.g., E.164 format: +12345678901)
3. Ensure proper access controls for phone number data
4. Include phone number as part of the user profile data model

### Error Handling
1. Display clear, specific error messages for invalid phone formats
2. Allow users to correct and resubmit invalid phone numbers
3. Log validation failures for monitoring potential issues
4. Handle special cases (e.g., extensions, toll-free numbers) appropriately

## User Experience
1. Provide real-time feedback on phone number format validity
2. Use appropriate input type (tel) for better mobile keyboard support
3. Consider offering country code selection for international users
4. Clearly indicate that the phone number is required for assessment calls
5. Inform users about how their phone number will be used (privacy considerations)

## Test Cases
1. **Valid Number Formats**: Verify acceptance of properly formatted phone numbers in various formats
2. **Invalid Formats**: Verify rejection of improperly formatted phone numbers with appropriate error messages
3. **Required Field Validation**: Verify the system requires a phone number to proceed
4. **International Numbers**: Verify support for international number formats
5. **Database Storage**: Verify phone numbers are correctly stored in the database
6. **Profile Association**: Verify phone numbers are correctly associated with the user's profile

### Phone Validation Example
```go
func isValidPhoneNumber(phone string) bool {
  // Strip all non-digit characters except leading +
  digitsOnly := regexp.MustCompile(`[^\d+]`).ReplaceAllString(phone, "")
  
  // Check if it starts with + followed by digits or just digits
  validFormat := regexp.MustCompile(`^\+?[1-9]\d{7,14}$`)
  return validFormat.MatchString(digitsOnly)
}
```

### Phone Storage Example
```go
func updateUserPhone(db *sql.DB, userID int64, phone string) error {

  formattedPhone := formatPhoneToE164(phone)

```

## Notes on SMS Verification
- The current MVP implementation does not include SMS verification through a verification code
- Phone numbers are collected but not verified via SMS in this initial version
- Basic validation of the phone format and comparison with resume data is used instead
- This approach prioritizes user experience flow while ensuring necessary data collection
- Future enhancements may include formal SMS verification if required
